# ADR-004：模块化单体加独立 Worker 进程

- **状态**：已采纳
- **日期**：2026-09-24

## 背景

项目包含 API、采集、Agent、报告和安全模块。个人开发需要清晰边界，但当前数据量和团队规模不支持微服务运维成本。

## 候选选项

1. 单体单进程：最简单，但长任务会阻塞 API，难以隔离失败。
2. 模块化单体 + Worker：一个代码库，API、Worker、Beat 分进程。
3. 微服务：独立伸缩，但部署、追踪和事务复杂度远超当前需求。

## 决定

采用模块化单体代码库，部署时区分 `api`、`worker`、`beat` 进程，共享 MySQL、Redis 和领域模型。

## 理由

该方案保留模块边界、异步任务和失败隔离，同时避免微服务的分布式复杂度和过度设计。

## 后果

- 正面：开发、调试和演示成本低，可自然演进。
- 代价：模块边界需要代码审查和依赖规则维护，不能任意跨层导入。
